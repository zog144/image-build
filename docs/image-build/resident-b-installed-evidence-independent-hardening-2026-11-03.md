# Independent Resident B installed-evidence verifier hardening — 2026-11-03

**Scope:** source-only review stacked on the *current* image-build PR #15 installed-evidence candidate `46ccdd5435778ff06d536b46d1ddd9cd84de2f52` and the earlier combined PR #14/#15 source contract `02fdd2f6b374322dd902ec58b982bbbf64d4b013`. This is deliberately **not** a second competing native verifier. Changes augment PR #15's single existing `tools/verify_resident_b_installed_evidence.py`, its synthetic fixture and a separate negative-test workflow.

## Independent gaps identified and corrected in source

1. **Missing interpreter/install inventory:** the original selected-controller inventory alone omitted the Python 3.12.16 executable, shared Python library and `_ssl`, `_sqlite3`, `_hashlib` output files. The verifier now unions the actual pinned `python-resident312/stages/final/produce-manifest.py` into its required installed-file list. All five must be present and identify as x86_64 ELF, and `python_version` is now exact `3.12.16`.
2. **Inexact extension ABI:** source previously accepted any `_ssl.`-prefixed path within Python's lib-dynload. It now requires the exact installed `cpython-312-x86_64-linux-gnu.so` extension paths, rejecting Python 3.15 and other ABI substitutions.
3. **Installed wheel semantic closure:** actual wheel `METADATA` must match Name/Version and exact `Requires-Dist` pins (`image-build==0.2.0.dev5`, `dbus-next==0.2.3`, plus `box-control==0.1.0` for root-control); `entry_points.txt` must name the original controller `console_scripts`; `WHEEL` must be purelib `py3-none-any`. All must be accounted for by installed `RECORD` hashes and the executable script record. The source parser handles the *specific* PEP 427-style `../../../bin/<controller>` entry while rejecting other path traversal.
4. **Privileged service identity:** the old verifier accepted a synthetic unit containing only selected strings. It now requires the complete installed `zog-root-control.service` bytes to equal the independently reviewed disabled source heredoc, not a new `Restart=always`/socket/STATE/activation stanza.
5. **Kernel mount permission separation:** `verify_protected_mounts` adds a distinct **native-only** physical check requiring real, separate rootfs and STATE mountpoints, protected root ownership of installed files and STATE, exact independently supplied mount-device identifiers and nonzero selected socket group, without permitting an automatic service-enable link. This check receives protected native installation identity from the host-install owner, **never from the untrusted receipt**. A disposable synthetic root correctly fails it.

The inherited PR #15 verifier already requires independently signed *separate-key* generation selection and native observation receipts and always returns `EVIDENCE_COHERENT_UNACCEPTED` even with valid signatures and synthetic installed bytes. This source integration preserves that trust separation, the unchanged box/root-control source pins, and explicit native/service NO-GO status. It does not authorize a selected generation, sign a real receipt, install keys, provision STATE, activate root-control, perform AWS operations, inspect real native ELF dynamic closure, or decide redistribution rights.

## Independent native prerequisites still held

The future protected host-install/runtime worker must authenticate the trust anchors' origin and revocation, independently selected immutable rootfs generation/STATE/Host binding, actual mount identity and root ownership, real installed wheel bytes and `RECORD`, exact Python/SQLite/OpenSSL functional imports and SSL trust, module and ELF `DT_NEEDED`/RPATH/loader origins, controller one-shot/privileged IPC, native service/socket GID admission and rights/notice delivery. Source CI uses only disposable synthetic Ed25519 keys and files.

**Disposition:** stronger native-acceptance interface prepared with source-only synthetic tests; **generation not accepted / boot not authorized**.
