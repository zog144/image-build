# Resident B protected installed-generation evidence interface — 2026-11-03

**Source-only review** stacked on the independent PR #14 + PR #15 combined source `02fdd2f6b374322dd902ec58b982bbbf64d4b013`. Code: `tools/verify_resident_b_installed_evidence.py`, synthetic tests: `tests/test_resident_b_installed_evidence.py`, isolated CI: `resident-b-installed-evidence-source.yml`. This is an evidence inspection library **not** a Host installer, trust-anchor provisioner, native compiler, authorized signer, generation acceptance agent or daemon.

## Two separate trust boundaries

1. **Independent host-install protected owner (not image-build):** authenticate the exact Host identity, installation, persistent STATE volume, selected rootfs generation ID and immutable installed-manifest hash. Install/retain two independently protected Ed25519 public keys/identities for the native worker and accepted-generation owner, and resolve STATE volume identity from authoritative selected installation evidence. The verifier accepts these as an externally supplied `zog-host-install-protected-resident-b-pins-v1` policy; it cannot infer that a caller-supplied policy was actually root-protected. Host-install must certify that provenance before trusting the result. Keys or acceptance authority are **never taken from the untrusted receipt**.
2. **Source verifier:** read a versioned `zog-resident-b-installed-generation-evidence-v1` receipt for the *exact* selected Source/Host/installation/STATE/rootfs/operation tuple. Deny missing/unknown schema fields, wrong source, fabricated `accepted` or `native_success` fields, absent source predecessors or unsigned/altered payloads. Verify the two Ed25519 signatures with separate domain prefixes. Even a correct signature and complete byte inspection only return **`INSTALLED_EVIDENCE_CONSISTENT` / `generation_accepted=false`**; independent protected installed-generation acceptance remains host-install/Work's separate operation.

An acceptance field or a signed-looking blob alone is not proof. SHA-256-sized plausible generation identifiers are never sufficient. The selected source and signature keys must be independently authenticated by the protected owner, and the actual native worker must produce the signed inspection evidence. The test-only `synthetic=True` path permits temporary user-owned files and a dummy STATE location strictly for source CI. It always returns `SYNTHETIC_EVIDENCE_CONSISTENT`, never accepted. This mode must not be called by native admission.

## Required installed evidence

- **Exact source graph:** Python 3.12.16 and all seven source-pinned CPython 3.12 build/runtime tool stages, both controller stages, OpenSSL, SQLite and systemd. Each prerequisite receipt carries the exact pinned original source SHA-256, immutable generation ID, installed-manifest SHA-256 and protected receipt digest.
- **Required installed outputs:** all Python 3.12 final-stage outputs; the root/box-control executable, source notice, package module, wheel METADATA/RECORD and root-control service source outputs from the combined PR #14/#15 record. Runtime evidence additionally requires both installed `entry_points.txt` and `WHEEL` with `py3-none-any` purelib tags, all referenced installed wheel members, and the exact controller `Requires-Dist` graph.
- **Real filesystem scan:** recomputed SHA-256/size, non-symlink paths, inode/size/time identity before-after read, exact modes/UID/GID and no hardlinked regular file shortcuts. Native-mode selected immutable rootfs files must be root-owned. `/usr/bin/python3.12`, `libpython3.12.so.1.0`, `_ssl`, `_sqlite3`, `_hashlib` must be x86_64 ELF by header, with a separately signed loader/DT_NEEDED closure using selected-root paths/digests. This reader does not substitute itself for the native worker's actual dynamic loader inspection.
- **Executable and source service:** controller scripts must have the expected `#!/usr/bin/python3.12` interpreter and executable mode 0755. The root-control service must be 0644 and byte-identical to the independently source-reviewed disabled systemd unit, including `Type=exec`, root identity, mount prerequisite and no activation section. No box-control global unit or unauthorized socket group is permitted.
- **Python runtime:** selected `/usr/bin/python3.12`, exact CPython 3.12.16/SOABI, completed authenticated interpreter invocation ID, SSL/OpenSSL and SQLite version observations, genuine imports of `ssl`, `sqlite3`, `_ssl`, `_sqlite3`, `_hashlib`, `zog.box_control`, `zog.root_control`; module origins pinned under the immutable 3.12 tree. Actual CA validation, SQLite WAL and HTTPS IPC tests remain separate native work.
- **STATE:** the receipt must bind the same operation ID, independent STATE mount device and root ownership/mode, with service disabled, no box-control global service, no automatic root socket grant. In production `/state` must be a real mount whose recorded device, owner and mode agree with the independently authenticated host-install policy. Presence of a `/state` directory alone is not enough.

The source checker does not claim to independently parse complete ELF dynamic tables, prove runtime import execution without the signed native worker, or establish that an arbitrary caller's public keys or acceptance policy were protected. Real native acceptance must separately verify all original signatures, selected tool origins and dynamic loader closure, required STATE roles, revocation/anti-replay and original rights/notice delivery. The source-only evidence interface deliberately retains those holds.

## Synthetic negative cases

The CI fixture builds temporary *fake* installed source files, `entry_points.txt`, `WHEEL`, `RECORD`, and synthetic ELF headers; signs one payload with two disposable test keys; and verifies that the result grants no authority. Mutation tests remove predecessor receipts, SSL module paths, output files and RECORD entries, alter wheel hash and entry point data, substitute the original source SHA, forge generation/STATE/service claims, use an untrusted key, corrupt signed evidence, mutate installed bytes or omit native loader observations. Production-mode inspection rejects the disposable non-root filesystem and absent genuine protected STATE mount.

**Outcome:** native-evidence shape and byte verification prepared with source-only CI. Resident B remains **NO-GO** pending a real accepted generation, protected host-install policy and native-worker evidence. No AWS/SSM/Host operation, service activation, compiler submission, key installation or rights clearance.
